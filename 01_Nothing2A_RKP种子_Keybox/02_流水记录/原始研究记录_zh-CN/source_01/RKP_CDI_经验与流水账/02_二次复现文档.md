# RKP 提取脱机调用二次复现文档

目标：复现 12 组 Google RKP attestation private key + 对应短期 certificate chain 的获取流程。

推荐工作根目录：

```bash
ROOT="<PROJECT_ROOT>"
FINAL="$ROOT/最终结果/rkp提取脱机调用"
FINGERPRINT="Nothing/PacmanEEA/Pacman:14/UP1A.231005.007/2401142323:user/release-keys"
SETTINGS_ID="668262"
```

## 0. 前提


## 3. 生成 sideleak patched TA

```bash
cd "$ROOT"
python3 rkp_research/patch_0706_rkp_sideleak.py
shasum -a 256 patched_ta/0706000000000000000000000000004d.rkp_sideleak.tlbin
```

期望：

```text
88f641c3cce8f98ed963481511853d60a9eb50b34344904cde27cba5632ce229
```

注意：这个 patched TA 用于 direct sideleak，不要 mount 到系统 KeyMint HAL 路径。系统路径实际加载 modified production `4d` TA 会导致 CSR `-100005`。

## 6. 运行 direct sideleak 12-key batch

```bash
cd "$ROOT"

RKP_DIRECT_TA="$ROOT/patched_ta/0706000000000000000000000000004d.rkp_sideleak.tlbin" \
RKP_DIRECT_GEEK="$GEEK_DIR/geek_curve_2.cbor" \
RKP_DIRECT_CHALLENGE="$GEEK_DIR/challenge.bin" \
RKP_DIRECT_TEST_MODE=0 \
RKP_DIRECT_KEY_COUNT=12 \
RKP_DIRECT_RUN_ID="direct_csr_batch_sideleak4d_$(date +%Y%m%d_%H%M%S)" \
python3 rkp_research/run_direct_csr_batch.py
```

成功的关键不是 CSR 成功，而是 keygen 和 scalar 验证成功。期望：


这里 `0xfffe795b` / `-100005` 是已知现象，不是失败终点。继续下一步。

## 7. 编译 stock Binder CSR client

```bash
cd "$ROOT"

"$NDK/bin/aarch64-linux-android33-clang++" -Wall -Wextra -O2 -std=c++17 \
  -static-libstdc++ \
  rkp_research/rkp_binder_csr_client.cpp \
  -o rkp_research/rkp_binder_csr_client \
  -lbinder_ndk -ldl
```

必须带 `-static-libstdc++`。第一次没有静态链接 C++ runtime 时，设备上报错：

```text
CANNOT LINK EXECUTABLE ".../rkp_binder_csr_client": library "libc++_shared.so" not found
```

最终二进制依赖应类似：

```text
libdl.so
libbinder_ndk.so
libm.so
libc.so
```

归档里已有可运行二进制：

```text
$FINAL/scripts/rkp_research/rkp_binder_csr_client
```

## 12. 避坑清单

```text
坑：用旧 challenge 发送 signCertificates
解：重新 fetch fresh GEEK/challenge，然后重新跑 Binder CSR。

坑：继续死磕 direct CSR 的 -100005
解：direct CSR 失败已确认；direct 只用于 keygen + scalar sideleak，CSR 交给 stock Binder。

坑：把 patched production 4d TA mount 到系统路径
解：系统实际加载 modified 4d TA 后 CSR 会 -100005；不要用它做系统 provisioning。

坑：只生成 1 个 key
解：stock 成功 CSR 是 12-key batch，keys_len=0x5c8。

坑：adb shell su -c 引号导致只有第一段命令以 root 执行
解：脚本中使用 su -c sh stdin 包装，整段设备脚本都在 root 下执行。

坑：/data/local/tmp 旧文件权限阻挡 adb push
解：push 前 root 清理旧目标文件。

坑：native Binder client 缺 libc++_shared.so
解：编译时加 -static-libstdc++。

坑：看到 "USING EEK ROOT KEY FROM VTS" 就判断失败
解：stock 成功 provisioning 也会出现该 warning；失败判据是 -100005 / Failed to generate CSR blob。

坑：fetch_google_geek.py 里有旧 ROOT 字符串
解：主逻辑用命令行 outdir，不依赖该 ROOT；按本文显式传参即可。
```
