# 能不能刷固件

## 结论

可以做“指定版本快速复现固件”，但不应该做“所有同型号通刷固件”。

## 判断表

| 情况 | 建议 |
| --- | --- |
| 同型号、同区域、同 build | 可以做快速复现包，最稳 |
| 同型号、当前设备版本更低，准备刷更高版本 | 通常可行，但仍要检查分区兼容 |
| 同型号、当前设备版本更高，准备刷更低版本 | 不建议，风险最大 |
| 同型号但区域不同 | 不要直接刷，先确认分区和 fingerprint |
| KeyMint TA hash 不一样 | 不要复用旧 patched TA，先适配当前版本 |
| TEE / LK / preloader 不一样 | 不要套旧 boot/TEE 包 |

## 最危险情况

```text
新设备已经升级到更高版本
你拿旧版本固件包去降级
```

可能结果：

- bootloader 拒绝启动
- vbmeta / AVB 校验不通过
- rollback index 拦截
- TEE / LK / preloader 不兼容
- 设备卡开机或需要救砖

## 正确做法

做版本矩阵，不做万能包。

```text
Pacman_U2.5_2401142323_fast_repro/
Pacman_U2.6_xxxxx_fast_repro/
Pacman_U3.x_xxxxx_fast_repro/
```

每个包必须写清楚：

```text
适用型号
适用 fingerprint
KeyMint TA hash
KeyMint HAL hash
TEE / LK / boot hash
是否允许从低版本升级
是否禁止从高版本降级
```

## 最安全建议

如果只是为了复现漏洞，不要优先刷全量固件。

优先：

```text
当前系统原地复现
```

只有当前系统缺少 root / patched TEE 条件时，才做最小刷入。
