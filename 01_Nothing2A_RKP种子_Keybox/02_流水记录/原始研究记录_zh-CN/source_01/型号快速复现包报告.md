# Nothing 2a 型号快速复现包报告

## 1. 结论

Nothing 2a 是当前两个目标里最适合做“快速答题包”的型号：同一台实机上已经闭合了传统 Keybox 的明文提取路线，也闭合了 `rkp_bcc_km` KDF 32 字节材料的导出路线。两条路线共用设备基线和 TEE 运行环境，但使用不同的 patched TA 和不同的采集客户端，不能把一个输出冒充另一个输出。

## 2. 已验证输入

| 项目 | 值 |
|---|---|
| SoC/TA | MT6886 / Trustonic TA UUID `0706000000000000000000000000004d` |
| OS | Android 14，Pacman U2.5 成功基线 |
| Keybox | 明文 8624 字节；EC、RSA 各 3 张证书；解析与链验证通过 |
| RKP KDF | label `rkp_bcc_km`，status 0，输出 32 字节 |
| 32 字节材料 | SHA-256 `e0e2617b...82a7c3`；原文不在报告中展示 |
| RKP 客户端 | `rkp_tee_probe_csr`，单密钥 direct path |

## 3. 复现包输入分类

- `06_固件与恢复/原厂_Pacman_U2.5-240301-2206/`：成功基线相关原厂镜像。
- `06_固件与恢复/已验证_补丁镜像/`：Keybox 只读路线使用的 TEE/LK/boot 输入。
- `03_patch与二进制/`：Keybox TA、RKP KDF TA 及其他历史研究补丁；只有入口文档点名的两个补丁可作为首选。
- `05_输入与支撑材料/source_binaries/`：精确 TA、TEE client、persist 输入和 host challenge/EEK 相关材料。
- `06_离线_google-rkp-sw/`：软件构造和审计材料；其中 `ctf_artifacts` 标记为敏感 CTF fixture。

## 4. 结果交付判定

### Keybox

交付目录必须含有：原始 TCI、before/after 缓冲区、明文 payload、EC/RSA 私钥 DER、各自证书链、解析报告、SHA-256 清单。只有私钥和对应叶证书 SPKI 一致且整链验证通过时才写 `PASS`。

### RKP CDI

交付目录必须含有：TA 哈希、设备运行日志、keygen `priv_full` 原始证据、32 字节 seed、KDF status、长度、marker、seed SHA-256。`seed_report.json` 是机器验收入口。seed 只说明当前实验中该 32 字节材料能作为软件 RKP 身份 seed 使用，不自动等同于所有平台的 UDS/CDI 原始根。

## 5. 不能写入结果的内容

- 不能把 Nothing 的每把 P-256 私钥标量和 `rkp_bcc_km` 32 字节材料混称为同一个秘密。
- 不能把本地 CTF fixture 的证书链写成 Google 生产证书。
- 不能把 HTTP 200 但没有同次私钥匹配的响应写成可用 keybox。
- 不能因为同型号就跳过 build fingerprint、TEE TA 哈希和槽位检查。
