# K70E tee_a v4 补丁实验结论（2026-09-03）

## 实验目的

验证：修正容器缺陷（LZ4 BD=0x40、BFSB section_size 同步、基于真实 preflash 备份、仅 4 个 8B 补丁、污染点全清除）后的 patched tee_a，能否通过 Secure Boot。

## 实验结果：被拒，boot-loop

- 刷入后重启 → Redmi logo 循环（boot-loop），`sys.boot_completed` 无法达到 1
- Secure Boot（芯片熔丝密钥，`img_auth=1 always`）拒绝修改过的 tee_a
- **结论：tee_a 补丁路线已闭环，不可行。根因不是容器/补丁实现，而是芯片熔丝密钥的镜像签名校验。**

## 实验设定（干净性核验）

- 基础镜像：`设备备份_只读_20260831_preflash/tee_a.bin`（SHA-256 `18227785891a3db4119fb3055ae09bb538a6a8e9ce874876b34d287386eaf21d`，真实原版）
- LZ4 容器：BD=0x40（64KiB 块，满足 bootsvc 硬校验 `(BD & 0x70) == 0x40`）、69 块、BFSB section_size 同步
- 补丁：4 个 8B，全部为 `mov w0,#0; ret`（`00008052c0035fd6`），覆盖两个 ta-mgr ELF 的 shdr_check_digest + shdr_verify_signature
- 污染点：0x096c18、0x0a6750 确认干净（非补丁）
- 代码级差异：32 字节（恰好 4×8B），无其他变化
- 成品 SHA-256：`74dccbe76cd3d304af628a64dabb7121b2f3b3925021bf08f74ccfb85795d6e2`

## 与 9/2 v3 的对照

| 项 | 9/2 v3 | 9/3 v4 |
|---|---|---|
| 容器 | BD=0x70（4MiB 块，bootsvc 拒绝） | BD=0x40（64KiB，正确） |
| 基础 | 有污染的 dump | 真实 preflash 备份 |
| 补丁 | 含神秘补丁 | 仅 4 个 8B，污染点确认干净 |
| BFSB | 过期 | 同步 |
| 结果 | boot-loop | boot-loop（确认根因） |

两次结果一致，排除容器/实现因素后，Secure Boot 铁板是唯一解释。

## 影响与后续路径

- **下一步不再做 tee_a 补丁实验**（已闭环）
- Secure Boot 分区（tee_a/lk_a/gz_a/preloader）只能刷回原版未修改镜像
- 升级路径只剩：
  1. LK 层镜像校验放行（Fenrir sbcen_unlock=2 → img_auth=1，已确认不可绕过）
  2. 芯片级密钥（超出当前可达范围）
- AVB 分区（boot/init_boot/vbmeta）的 Magisk/init_boot 补丁路径仍然开放，但 v5 现场已证明 CSRv3 链路无主机可见私密出口，root shell 不能进入 TEE——预期收益有限

## 恢复

设备经免费 preloader-catch 方法（SPFT 自动扫描抓 PID_2000 窗口）刷回原版 tee_a 恢复，0 卡密。
