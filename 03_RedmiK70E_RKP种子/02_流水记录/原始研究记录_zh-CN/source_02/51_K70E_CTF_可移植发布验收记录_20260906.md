## 3. 恢复路径故障注入

已覆盖以下不可逆边界：

- capture 的 device preflight boot ID 必须在 Binder latch 的同一 root 事务内、`mkdir` 之前再比较；
- 延迟冻结 collector `finally` 的 exact remote `rm`，必须先证明主机有同轮可用 scalar；
- 主机 scalar 缺失时，只从 Binder latch 的 exact remote path/固定文件名拉回，验证 32-byte P-256 与同轮 CDI_Leaf SPKI，落盘后才清理远端；
- `MacedPublicKey` 只是 transport 旁证，不是身份；它缺失不阻断已有 native CSR + scalar 的密码学恢复；
- 在 canonical/public/summary 中任一原子写入之后崩溃，重复恢复仍幂等；duplicate 只在全部耐久提交后删除；
- Google 返回后立即递归 `fsync` 文件、chain 目录、output 与父目录，再删 frozen scalar/进入耗时审计；
- attempt/network/SUCCESS 使用完整 temp + `fsync` + atomic no-replace publish，不会因中途断电留下截断的终态 marker；
- SUCCESS 权威副本与 provision 副本之间崩溃后，`--resume-finalize` 只接受完整绑定证据并幂等补齐；
- issuance attempt/network/SUCCESS/run summary 共同绑定 canonical output path 及其父目录 device/inode，换 output-dir 会拒绝；
- resume 只能补齐缺失 summary 字段；已有字段冲突或 runtime profile snapshot 字节不同必须拒绝，不会“洗白”证据。

故障注入结果：

- canonical/public/summary 中断后身份恢复可幂等完成；
- 只有远端 scalar、可选 MACed 文件缺失时，仍能先抢救身份再清理；
- `--resume-finalize` 连续执行两次，SUCCESS 两副本 SHA-256 保持不变；
- 把已签发 output 复制到另一路径后 resume 被拒绝；
- 重复 `--preflight-only` 被拒绝；非 Google 官方 endpoint 在创建 output 前被拒绝。
