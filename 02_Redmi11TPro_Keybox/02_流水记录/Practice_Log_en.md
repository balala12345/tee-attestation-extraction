# Redmi 11T Pro: Full practice ledger (sanitized)

> **Documentation provenance and reproduction note:** The organization, splitting, translation, sanitization, and chapter arrangement of this directory were produced by an AI reading the existing project tree, source documents, practice ledgers, and artifact manifests. The public copy does not represent manual execution, independent reproduction, or sign-off for every command, patch, image, or result. “Tutorial,” “result,” and “acceptance” refer to source records, evidence models, or AI-organized conclusions; they do not mean that the public copy has been independently validated, and they are not guaranteed to work outside the complete project context. The intended workflow is to have an AI read the complete target-device directory and produce prerequisites, version/hash gates, invalid routes, missing evidence, and steps requiring validation, then have an authorized human review each item in an isolated environment. Never execute an AI-generated command without human review.


1. A complete baseline was captured before modification: properties, kernel and permissions, slot state, TEE devices, KeyMint services, mounts, partition links, boot/TEE images, TA set, and client library.
2. The stock client was run first and its failure output was saved. This was the control proving that the final payload did not come from an already-working client.
3. Temporary privilege attempts were iterated. The ledger keeps the forward-task-list failure, tail-chain miss, UID-0-without-capabilities failure, kernel-domain exec denial, and over-strict SELinux precheck. These failures explain why a root prompt alone was not accepted as a prerequisite.
4. Static analysis identified the Keybox TA, the existing read command, the parameter-type gate, and the caller-mode gate. The TA patch changed only the caller-mode comparison. The secure-manager patch allowed the modified container to continue through its normal unwrap/decompress flow.
5. The TA was re-packed with updated module sizes and MD5 values. Offline AES-CTR read-back and the module manifest were checked before deployment.
6. The exact test-slot LK/TEE chain was built. Before writing, both slots were backed up and hashed. Only the test slot was written; complete read-back and untouched-slot checks passed.
7. During the successful run, the temporary root session had UID 0, the required capabilities, and the expected SELinux state. The service was stopped, the patched TA was mounted temporarily, the read command returned success, and the payload/descriptor sizes were recorded.
8. Offline parsing found one EC entry and one RSA entry, each with a three-certificate chain. Descriptor magic, payload MD5, private-to-leaf public-key equality, chain signatures, and private-key signing all passed.
9. The final copy contains the verified patches, images, firmware, parser, evidence logs, and a full source-record directory. Raw Keybox/private-key contents, serials, host paths, and user identifiers were removed.
