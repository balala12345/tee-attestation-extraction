因此，文档中的“教程”“结果”“验收”“成功”“失败”和“当前路线”必须结合来源记录和时间上下文理解。它们可能是来源工程中的历史记录、AI 根据证据整理出的判断、未完成状态或需要重新验证的结论，不等同于人工验证通过，也不保证脱离完整工程目录后可以直接执行。

本项目推荐的复现方式是 **AI 辅助阅读 + 人工授权复核**：

1. 将目标设备的完整目录提供给 AI，而不是只提供单个 README 或一段命令；
2. 让 AI 先提取前置条件、版本/槽位/哈希门禁、输入材料、失败路线、回滚条件、缺失证据和待确认矛盾；
3. 让 AI 输出只读复核计划和人工确认清单；
4. 由具备授权和设备操作能力的人工在隔离、可回滚环境中逐项检查；
5. 只有人工确认输入、环境和风险后，才决定是否执行任何操作；
6. 将实际执行结果、偏差和未验证项写回流水记录。

AI 生成的命令、补丁解释、路径推断和结果结论都不能直接视为可执行指令或人工认证结果。只阅读 README、只复制命令、只看到一次成功启动，均不足以证明复现成功。

## Fenrir 的研究角色

Fenrir 在本工程中只作为授权实验室中的启动链研究基础。公开资料层面只描述其作用边界：它针对 MediaTek 启动链中的验证边界问题，使研究人员可以在受控设备上观察后续启动阶段的行为。具体的补丁构建、刷写命令、TEE/KeyMint 旁路和真实密钥材料不放入公开工程。

本项目不把“能够启动研究环境”自动等同于“已经提取成功”。每个设备都必须同时满足版本、型号、槽位、镜像哈希、运行时能力和结果公钥匹配等门禁。

## 方案原理概述

本方案的核心链路可以概括为：**Fenrir 启动链研究基础 → 受控加载研究组件 → 匹配版本的 TEE 诊断补丁 → 主机侧结果解析与验收**。

Fenrir 利用的是启动链中的验证边界缺陷。在设备满足授权实验前置条件时，它帮助研究人员绕过后续启动组件原本的完整性验证约束，从而进入可控的研究环境。这里绕过的是启动链的加载与验证边界，不等同于普通应用权限，也不意味着仅安装 APK 或取得 ADB/root 就能直接访问 TEE。

进入研究环境后，针对具体机型、系统版本、槽位和 TA/TEE 版本使用对应的诊断性 patch，对 TEE 相关调用链进行受控观测和结果提取。Keybox、RKP CDI/seed 和证书材料分别走独立的结果验证流程，必须通过长度、结构、哈希、公钥匹配和证据回溯，不能把日志、证书或模拟数据直接当成真实提取结果。

Fenrir 本身不生成厂商签名、不伪造 Google 证书，也不把普通系统权限升级成永久 TEE 权限；TEE patch 也不是通用固件，必须与目标版本和输入哈希严格匹配。公开工程只保留原理、接口、合成夹具和审计规则，设备专用 patch、刷写材料和真实秘密属于授权内部材料。

## 结果验收门禁

以下是来源记录中应检查的验收条件和公开复核门禁，不代表本公开副本已经完成人工独立验收。每一项提取结果都应按独立结果类别检查，不能把日志、证书、模拟数据或单次成功启动当成最终结果。至少检查以下项目：

- **目标一致性**：设备型号、构建版本、系统版本、槽位和运行时组件必须与记录一致；
- **输入一致性**：原始输入、补丁输入、镜像和固件包必须通过清单中的 SHA-256 校验；
- **环境一致性**：引导状态、研究组件、TEE/KeyMint 服务、权限和运行能力符合教程门禁；
- **结果结构**：长度、编码、字段、容器格式和解析结果满足对应结果类别的约束；
- **密钥与证书关系**：公钥、证书链、签发关系、RKP/CDI 关系和同轮证据可以相互验证；
- **来源可追溯**：结果能回到对应流水记录、输入文件、版本、槽位和原始证据；
- **公开安全性**：公开副本不包含真实 Keybox、seed、私钥、设备唯一身份字段、令牌或原始身份响应。

任何门禁不匹配时都应停止当前路线，在流水记录中写明原因；不能通过修改清单或删除失败证据来制造通过结果。

7. 重新执行设备验收，确认结果证据和公开边界后再发布。

## 公开发布复核清单

提交或重新发布前，建议逐项确认：

- 默认入口是中文 `README.md`，语言栏为 `中文 | English`；
- `README_en.md` 与中文 README 的章节、链接和公开边界保持对应；
- 三个设备目录均包含教程、流水、原理、补丁/镜像/固件和索引；
- 中文与英文主文档均可从项目入口或设备目录互相找到；
- 每个设备的 SHA-256 清单与当前公开副本一致；
- 文档、脚本、日志、JSON、二进制和压缩包中没有个人路径、用户名、序列号、令牌或真实秘密；
- 历史失败记录未被删除，失效路线有明确标记；
- 第三方许可证、版权声明和 NOTICE 未被覆盖；
- 原创脚本、原创文档和第三方材料没有被错误地声明为同一个许可证；
